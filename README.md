# 伴行 · 你先走，我看着路

**Problem-solving of authentic challenges** —— 帮助人们用 AI 解决真实世界问题的协作者。

和一个很强的模型做一段长对话，最危险的不是它哪一步做不好，而是**整段对话慢慢走到了一个不太对的地方，却没有人察觉**：
模型认自己的账——它说过的话，自己往后一直当真；你只读最新一轮，回一句「好，继续」；第 7 轮随口的一句「这个应该没问题」，
到第 40 轮已经成了地基。

伴行（Banxing）是一个待在旁边的小应用。你选一条正在进行的长对话，它请**另一个模型**在旁边读：记下这段对话立在什么上面，
回头去查那些只是说过、没有查过的地方；思路走偏时提醒你一句，并给一句可以原样带回去问的话。

```
前提没查过                                                              ×
「同一份索引」只是说过，后面的归因都靠它
第 3 轮的说法没有任何记录支持，第 6 轮却据此把差别全部归给了重排模型。
它影响：两套方案的索引如果不同，提升可能来自索引而不是重排，结论要重做。
最省事的核验：打印两套方案的索引路径和构建时间。

  可以原样带回去问主模型：
  你在第 3 轮说 A 和 B 用的是同一份索引。请贴出两套方案各自的索引路径和构建时间；
  如果没有实际核对过，请现在核对并给出输出。

  第 3 轮 · 主模型说：「A 和 B 用的是同一份索引」
  眼下正靠它往前走的一步：
  第 6 轮 · 主模型说：「差别只能来自重排模型」

收起依据   复制这句追问   我知道，有意如此   这条不成立
```

它不是又一个附和的声音。让第二个模型的旁听真的有用，靠的是五件事（详见 [`docs/design.md`](docs/design.md)）：

| | |
| --- | --- |
| **账本，不是摘要** | 在对话之外记一本账：你想回答的问题，和这段对话的立足点。每个立足点凭什么成立由**应用**判定——有记录或有你的原话才算「有依据」；只有主模型自己说过的，算「没查过」。**主模型的话不能给主模型的结论作证。** |
| **独立一读** | 第二个模型读了四十轮自信的论述，也会被带着走。所以它可以要一份独立一读：只看你的话和实际的运行记录，主模型说过的每一句都拿掉，再和主模型的走向比对。 |
| **它自己决定去查什么** | 重读旧轮次，在全文里搜一个词。搜不到也是答案——「从头到尾没人验证过」就是这样查出来的。 |
| **一句能带回去的话** | 每个疑点配一句中立、具体、要对方拿出证据的追问，点一下就复制。发不发由你；主模型怎么回答，伴行接着读。 |
| **克制** | 引文对得上原文、正在影响方向、你还没发出下一条——三样都满足才出声；同一件事只说一次；你说「有意如此」或「不成立」，它就不再提。绝大多数时候它不说话。 |

它认六种「走偏」：目标漂移、前提没查过、结论超出证据、前后矛盾、过早收窄、原地打转。
伴行**只读**，不往任何应用里写一个字。目标和每一步都由你定。任务怎么拆、想法怎么问清楚，交给 `grill-me` 这类技能；伴行管的是开工之后。

## 怎么用

Windows：到 [Releases](https://github.com/QShin21/collaborator/releases) 下载安装版（`…-setup.exe`，按用户安装，不需要管理员权限，
可在「设置 → 应用」里卸载；升级和卸载都不动 `%APPDATA%\Banxing` 里的数据）或便携版（`….zip`）；也可以从源码运行（见下文）。
第一次启动会弹出使用说明（以后在右键菜单里）。右键伴行 → 「旁听用的模型…」，配置在旁边读对话的那个模型——**最好不是你正在对话的那一个**。
没有密钥想先看流程，可以选「离线演示」。

| 你做什么 | 伴行做什么 |
| --- | --- |
| 右键伴行 → 「旁听一条对话…」，选一条：在聊天网页里全选复制后「从剪贴板读取」；或一份 ChatGPT 导出；或 Codex / Claude Code 的会话；或一份文字稿 | 只在本机读它，列出里面的对话让你选。这一步不发送任何东西 |
| 定范围（从第几轮开始读），看清这条对话会发往哪个地址、用哪个模型，点「同意并开始旁听」 | 把允许范围内的历史读一遍，建账本 |
| 照常和主模型工作 | 主模型每结束一轮、你还没发出下一条时看一眼。只提交新增的轮次、账本指向的几轮和最近三轮；其余的它想看再自己回头查 |
| —— | 思路走偏且正在影响方向：出**一条**气泡。否则只更新账本 |
| 点「复制这句追问」，粘贴给主模型 | 账上记下「带回去问了」。主模型的回答里有了实际的记录，这一条就从「没查过」变成「有依据」 |
| 点「我知道，有意如此」或「这条不成立」 | 记下（可以补一句理由，旁听的模型下次会看到）。这一类疑点不再出现，直到目标或立足点真的变了 |
| 发出下一条消息 | 旧气泡收起 |
| 点一下伴行，或右键 → 「现在看一眼」 | 现在就看。任何时候都有回答：最重的一处疑点，或者「没有发现走偏，因为……」 |
| 右键 → 「账本…」 | 看整本账：哪些有依据、哪些没查过；这次它回头查了什么；提交过哪些轮次、多少字、几次请求。可以更正目标、看上次提交的全文、看独立一读的原话、开关加密保存、结束旁听 |
| 网页聊天又长了 | 再全选复制一次，右键 → 「对话有更新：从剪贴板再读一次」 |
| 改写了早先的消息、换了分支 | 伴行停下，不再提交，等你在账本里确认旁听哪一条 |

不开界面也可以：

```
python run.py --watch 导出.zip --list                                   # 这份导出里有哪些对话
python run.py --watch 导出.zip --conversation ID --agree https://实际地址  # 账本 + 看一次
python run.py --watch 会话.jsonl --stepwise --agree https://实际地址      # 逐轮回放：哪一轮之后它会出声
```

## 隐私与安全

- **逐条同意。** 开始旁听的窗口写明这条对话从第几轮起发往哪个地址（协议、主机、端口）、用哪个模型；同意只对这条对话、这个地址有效。
  地址一变（包括用环境变量覆盖）立刻停止，直到你重新确认。命令行每次运行都要用 `--agree` 写明地址。
- **范围是硬的。** 你指定的起始轮次之前的内容任何情况下都不提交——旁听的模型主动要也不给。
- **看得见。** 账本底部一直写着：读到第几轮、提交过哪些轮次、多少字、几次请求（回头查和独立一读的也算）、发往哪里。看起来像密钥的文字会先被隐去。
- **对话不复制。** 伴行只记住去哪里再读它。账本默认只在内存里，退出即失；勾选之后才加密保存在本机（Windows DPAPI，加密失败就不保存并告诉你），
  结束旁听或「清除本机数据」即删除。
- **对话内容只是资料。** 旁听模型的回复在显示前逐条回查：引文在它说的那一轮里原样找得到才算数；出现对话里没有的网址、把内容发到别处、
  下载后直接执行、要求忽略先前指示之类的内容，整份回复丢弃。
- API Key 用 Windows DPAPI 加密保存（加密失败就不保存，绝不改存明文），并绑定到输入它时的服务和接口地址：更换地址必须重新提供 Key。
  模型服务返回的跳转一律不跟随；请求失败不会改写后重发，也不会自己重试。
- 伴行不读也不写任何应用的窗口，不替你发送任何东西。本机的统计（`%APPDATA%\Banxing`）只有数字和代号，不含对话内容。

## 从源码运行

需要 Python 3.9+（带 tkinter）。核心只用标准库；托盘图标可选，需要 `pystray` 和 `Pillow`。

```
pip install -r requirements-windows.txt      # 仅 Windows，可选（托盘图标）
python run.py                                # 启动伴行（Windows 上也可双击 start.bat）
python run.py --watch 文件                    # 读一条对话，打印账本和疑点（--stepwise 逐轮回放）
python run.py --replay                       # 11 段带标注的对话逐轮回放：时机、准头、误打扰、主动性、一次性对照
python run.py --selftest                     # 自检
python run.py --summary                      # 本机试用记录汇总（出声几次、带回去问几次、不成立几次……）
python -m unittest discover -s tests -v      # 测试
```

没有模型密钥时，设置环境变量 `BANXING_PROVIDER=mock` 可用离线替身体验流程（关键词规则，**不代表任何判断质量**；
用它跑的回放报告会自动标为「仅流程」）。其他环境变量见 [`.env.example`](.env.example)。

## 项目结构

```
banxing/
  watch/           旁听一条长对话
    transcript     对话模型：一轮 = 用户的话 / 主模型的话 / 记录；引文回查、全文搜索、只留证据的渲染（纯函数）
    sources        读取：剪贴板里的聊天页面、ChatGPT 导出、Codex 会话与 App Server、Claude Code 会话、文字稿
    ledger         账本，以及「凭什么成立由应用判定」的规则（纯函数）
    audit          一次审查：多步（回头查、搜索、独立一读）、校验结论、安全闸
    nudge          什么时候可以出气泡（纯函数）
    session        一条对话随时间的推进：何时审查、提交什么、用户的回应、分支核对（纯函数）
    vault / driver 加密落盘（用户勾选才有）；与界面和线程的接线
    standin        离线替身（关键词规则，仅供测试和演示）
  prompts/         提示词（Markdown，带版本号，每次调用重新读取）：audit、blind
  llm.py / mock.py 模型接入（Anthropic / OpenAI 兼容 / 离线替身）
  evalkit/         带标注的对话与逐轮回放
  context/         Codex 自己的数据：App Server、会话 JSONL（只读）
  ui/              文案（中英）、视图模型、Tk 外壳
  lint.py          安全闸                    textutil / jsonutil / geometry   小工具
  config / secretbox / store / executor / winshell   设置、密钥加密、本机记录、线程、Windows 外壳所需的系统调用
  cli.py           入口：运行 / --watch / --replay / --selftest / --summary
docs/
  design.md        产品设计与实施状态
  verification.md  证据台账                 acceptance.md  验收手册
  evidence/        证据记录                 release-notes/ 各版本的发布说明（中文功能与使用说明）
tests/             离线测试，只用合成数据
packaging/windows/ 随包说明、安装程序脚本（Inno Setup）、构建与安装检查脚本（PowerShell）

```

## 发布新版本

1. 修改 `banxing/__init__.py` 里的 `__version__`，更新 `docs/verification.md` 的台账，写 `docs/release-notes/v版本号.md`。
2. 打 `v*` 标签并推送（或在 Actions 页面手动运行 `release` 并填版本号）。
3. GitHub Actions 在 Windows 上跑测试，用 `packaging/windows/build.ps1` 打包（PyInstaller → 打包结果自检 → 便携 zip → Inno Setup 安装程序），
   用 `verify-installer.ps1` 在那台机器上真装、真跑、重装、卸载一遍，然后把安装程序和 zip 发布为预览（pre-release）。
   同名的 Release 已存在时工作流会停下，不覆盖。每次推送的 CI 也跑同样的打包和安装检查，只是不发布。
   **`release.yml` 本身还没有运行过**（0.4.0a1 是用一次性工作流发的）。工作流全绿只说明到 E2；发布说明里不得写成判断质量已评估。

## 来历

项目发起人最初的设想（原话）：

> 制作一个帮助人们使用ai解决真实世界问题的的ai-collaborator，**problem-solving of authentic challenges。**
>
> 学生行动：学生主动描述问题、提出问题、提出目标、提出即使是模糊的想法，即结构良好问题或者结构不良问题，作为agent的大前提；学生探索问题的具体任务、解决问题等。
>
> AI行动：1.读取并理解结构良好问题或提供脚手架解决结构不良到良好的gap（实现原理：提供广度的知识，提供有可能的一些脉络，主线支线，然后给人选择）；
> 2.在读屏之类的基础上，提供冒泡式的idea，具有启发性、建议性，一定时长后冒泡淡化，或人主观地参考冒泡idea进行深入讨论与学习；人的反馈可以调整agent的能动性和偏好，接受、忽略、扩展讨论都会对agent进行调整
>
> 改造前后的对照：用不同的agent，前后测与横评。

v0.1.0 把它做成了本地 Web 工作台（见 tag `v0.1.0`，代码存档在 `legacy/v0.1/`）。一代（0.2，未发布）和二代（v0.3.0，更名为伴行）
做的是面向 Windows Codex 的桌宠：人先写草稿，AI 给三条路线、分出主线支线让人选，并随着人越写越好而越说越少——存档在 `legacy/v0.3/`。

2026 年 11 月，发起人提出：前沿模型对提示词的要求已经很低，帮人把话问好不再是最要紧的事；更要紧的是**一个模型对自己做的东西太容易认可**，
长对话会因此走偏，而在不同模型之间流转内容又很不方便。于是伴行推倒重做成现在的样子：人仍然先行动、仍然自己做每一个决定，
另一个模型在旁边看着路，冒泡只在走偏的时候出现，人的回应——带回去问、有意如此、不成立——仍然在调整它说不说话。

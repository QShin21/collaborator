# AI Collaborator

**Problem-solving of authentic challenges** —— 一个帮助人们用 AI 解决真实世界问题的协作者。

很多人用不好 AI，不是因为 AI 不够强，而是因为真实问题往往是**结构不良**的：目标模糊、条件没说、
没有唯一答案。普通聊天助手会默默挑一种理解然后给出一大段答案，人要么照单全收，要么不知道怎么追问。
AI Collaborator 要消除的就是这个 gap：**问题始终由人提出和主导，AI 负责把模糊变成可动手，并在旁边适时冒出启发。**

```
python3 run.py          # 打开 http://127.0.0.1:8765
```

零依赖：只需要 Python 3.9+（标准库），不用 pip / npm / 构建。没有 API Key 时自动进入离线演示模式。

### Windows 用户（无需安装 Python）

到本仓库的 [Releases](https://github.com/QShin21/collaborator/releases) 页面下载
`AI-Collaborator-<版本>-windows-x64.zip`，解压后双击 `AI-Collaborator.exe`，浏览器会自动打开。
首次使用点击页面左下角的"⚙"状态标签填入 API Key。数据保存在 exe 同目录的 `data\` 下。
程序未签名，SmartScreen 提示时选"更多信息 → 仍要运行"。

从源码运行可双击 `start.bat`。

**发布新版本**：改 `collab/__init__.py` 里的版本号，然后 `git tag v0.1.0 && git push origin v0.1.0`
（或在 Actions 页面手动运行 `release` 工作流并填版本号）。GitHub Actions 会在 Windows 上跑测试、
用 PyInstaller 打包、对打包结果做启动冒烟测试，并把 zip 发布到 Releases。

## 原始设想（项目发起人原话）

> 制作一个帮助人们使用ai解决真实世界问题的的ai-collaborator，**problem-solving of authentic challenges。**
>
> 学生行动：学生主动描述问题、提出问题、提出目标、提出即使是模糊的想法，即结构良好问题或者结构不良问题，作为agent的大前提；学生探索问题的具体任务、解决问题等。
>
> AI行动：1.读取并理解结构良好问题或提供脚手架解决结构不良到良好的gap（实现原理：提供广度的知识，提供有可能的一些脉络，主线支线，然后给人选择）；
> 2.在读屏之类的基础上，提供冒泡式的idea，具有启发性、建议性，一定时长后冒泡淡化，或人主观地参考冒泡idea进行深入讨论与学习；人的反馈可以调整agent的能动性和偏好，接受、忽略、扩展讨论都会对agent进行调整
>
> 改造前后的对照：用不同的agent，前后测与横评。

## 它怎么工作

| 设想 | 实现 |
|---|---|
| 学生主动描述问题、目标、模糊想法 | 首页只有一个必填框：把问题想到哪写到哪。目标和已有想法可选。AI 不会先开口。 |
| 读取并理解结构良好问题 | **诊断**：判断问题是 结构良好 / 部分清晰 / 结构不良，并用学生的话复述、列出已知与未知。结构良好的问题直接生成问题卡开工，不加多余的脚手架。 |
| 脚手架：从结构不良到结构良好 | **方向地图**：① 最多 3 个最能改变方向的澄清问题；② 知识版图（广度：这个问题会碰到哪些领域）；③ 若干条真正不同的脉络，标注**主线 / 支线**、今天就能做的第一步、走这条线会学到什么。学生勾选或写自己的方向。 |
| 然后给人选择 | 选择之后生成**问题卡**（目标、已知、限制、成功标准）和任务列表——这就是"结构良好"的版本，全部可由学生编辑。AI 的假设会标注"(假设)"等待纠正。 |
| 学生探索具体任务、解决问题 | **工作台**：左边问题卡与任务，中间对话，右边工作笔记。AI 能看到整个工作台，对话时以此为共同语境。 |
| 读屏 + 冒泡式 idea | AI 持续"看着"工作台（笔记、对话、任务进度、选中的文字），可选**共享屏幕**后还会看真实屏幕截图。内容有变化或你停顿较久时，屏幕角落浮起 1–3 个**冒泡**：提问 / 换个视角 / 知识 / 下一步 / 盲点 / 联想。 |
| 一定时长后淡化 | 每个冒泡有寿命，逐渐变淡后消失；鼠标悬停时暂停并显示"为什么冒这个泡"。 |
| 参考冒泡深入讨论 | **展开聊**：把冒泡变成一段对话的起点。**收下**：放进"收下的想法"。 |
| 反馈调整能动性与偏好 | 展开 / 收下 / 淡化 / 忽略 四种反应会同时调整：**主动性**（冒泡频率、数量、停留时长、对话中的主动程度）与**偏好**（六类冒泡各自的权重）。状态完全透明，可手动拖动、锁定、暂停、重置；并缓慢沉淀进跨会话的**长期画像**。 |
| 改造前后对照：不同 agent、前后测、横评 | **对照实验室**：四个智能体（见下）；每个会话可做**前测 / 后测**（自评量表 + 开放作答由评分模型按量规打分）；**盲评竞技场**并排比较不同智能体对同一问题的第一反应；`eval/run_eval.py` 用模拟学生做**批量横评**。 |

### 四个可对照的智能体

| 名称 | 脚手架 | 冒泡 | 说明 |
|---|---|---|---|
| `collaborator` | ✓ | ✓ | 完整版（本产品） |
| `scaffold` | ✓ | ✗ | 消融对照：只看脚手架的贡献 |
| `socratic` | ✗ | ✗ | 只提问、不给内容的"苏格拉底式"导师 |
| `baseline` | ✗ | ✗ | 普通聊天助手（"改造前"） |

## 配置模型

最简单：点击页面左下角的"⚙"状态标签，在界面里填。或者复制 `.env.example` 为 `.env`：

```
ANTHROPIC_API_KEY=sk-ant-...
# 默认：COLLAB_MODEL=claude-fable-5-2，COLLAB_EFFORT=medium
```

也支持任何 OpenAI 兼容接口（`COLLAB_PROVIDER=openai` + `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `COLLAB_MODEL`）。
共享屏幕读屏需要支持图像输入的模型。数据保存在本机 `data/collab.db`（SQLite）。

### 安全边界

应用在本机保存你的工作内容和 API Key，所以服务端只响应真正发给它的请求：

- `Host` 必须是 `127.0.0.1` / `localhost`（或 `COLLAB_ALLOWED_HOSTS` 中列出的名字）——防止 DNS 重绑定；
  `Origin` 必须是应用自己的地址；跨站请求一律拒绝。
- 模型设置只能在运行应用的这台电脑上修改；**修改接口地址必须重新输入 API Key**，已保存的 Key
  不会被发往新的地址；接口地址必须是 https（本机地址除外）。

### 切到其他窗口时

- 冒泡的"寿命"只在你看得见它的时候流逝：切走期间不会被记为"淡化"，回来后继续。
- 没有共享屏幕时，页面在后台不会生成冒泡。
- 共享屏幕并允许系统通知后，你在其他窗口工作时，屏幕内容有变化就会以**系统通知**的形式冒泡；
  通知停留一个寿命后无人理会才记为"淡化"。未允许通知则不在后台冒泡。
- 浏览器会给后台标签页的计时器降频（长时间后台约每分钟一次），所以后台冒泡的间隔可能比设定的长。

## 做对照实验

**会话内前后测（真人）**
1. 新建问题时展开"对照实验设置"，选择智能体，完成前测。
2. 正常协作。
3. 点"收尾 · 后测"。立刻看到本次的前后对照；"对照实验室"按智能体汇总增益、主导感、帮助度。

**盲评竞技场（真人）**：在实验室输入一个问题，三个智能体匿名作答，打分后揭晓。

**批量横评（模拟学生）**

```
python3 eval/run_eval.py                                   # 全部场景 × 全部智能体
python3 eval/run_eval.py --agents baseline collaborator --turns 4
```

每组（场景 × 智能体）：模拟学生前测 → 与智能体协作若干轮（会选线、会用或忽略冒泡）→ 后测 →
评分模型盲评两次作答与完整对话（脚手架、主导权、广度、进展、效率）。报告写入 `eval/reports/`。
场景在 `eval/scenarios.json`，包含结构不良、部分清晰、结构良好三类，可自行增补。

> 模拟学生 + 模型评分只是低成本的初筛，结论需要用真人前后测确认。
> 离线 mock 模型的评分是固定值，只用于验证流程能跑通，不代表任何质量结论。

研究数据导出：实验室页"导出全部研究数据"，或 `GET /api/export`（会话、测验、冒泡、事件日志、横评）。

## 迭代与升级

项目按"长期使用、持续迭代"组织：

```
collab/
  engine.py    协作者本体：诊断、地图、问题卡、对话、冒泡、反馈、前后测、横评、统计
  adapt.py     主动性与偏好的自适应规则（纯函数，改参数只动这里）
  llm.py       模型接入（anthropic / openai 兼容 / mock）
  mock.py      离线替身模型
  db.py        SQLite 存储，带版本化迁移（只追加 MIGRATIONS）
  server.py    JSON API + 静态文件
prompts/       所有提示词，纯 Markdown，运行中修改即时生效
web/           前端（原生 JS，无构建），i18n.js 含中英文案
eval/          模拟学生批量横评
tests/         单元与端到端测试（离线运行）
```

推荐的改进循环：**改 `prompts/` 或 `adapt.py` → `python3 -m unittest discover -s tests` →
`python3 eval/run_eval.py` 对比报告 → 真人前后测确认**。新增一个对照智能体只需在 `engine.py`
的 `AGENTS` 加一行并提供提示词。

### 后续方向

- 流式输出；对话中的分支讨论（冒泡展开为独立线程）
- 浏览器扩展 / 桌面端，让读屏覆盖任意应用而不只是工作台与共享屏幕
- 冒泡时机模型：从固定节奏升级为根据卡顿、反复修改等行为信号触发
- 长期画像扩展到知识掌握与兴趣（跨问题迁移）
- 多人协作与教师视图；延迟后测（保持与迁移）
- 更严格的评测：多评分者一致性、真人对照实验模板

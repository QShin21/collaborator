## 0. 一页摘要

**伴行是什么**：一个陪人用 AI 把真实问题做下去的桌面伙伴。人先开口，它在旁边把路看清：给几条走得通的路线、提醒漏掉的一句话、
在成果回来时说一句「先做这个」。它不替人发送，不替人决定，并且随着人越来越会写而越来越安静。

**一代（开工桌宠，v0.2.0，尚未提交和发布）的现状**：产品逻辑完整；离线测试共 226 项，在 Linux 上 217 项通过，另外 9 项只能在 Windows 上运行、在本机跳过。但——

- Windows 这一侧的代码（读输入框、回填、认聊天、不抢焦点、打包）**一行都没有在 Windows 上运行过**；
- 没有对真实 Codex 做过任何验证；没有用真实模型生成过一次建议；Windows CI 从未运行；
- 也就是说，一代目前是「逻辑成立、是否能用未知」。

**二代的十三条意见**（第 3 节展开），归成四件事：

1. **先变成真的**：证据先于功能。做一套校准与证据工具，让一个有 Windows + Codex 的人花半小时就能产出一份不含内容的证据包；
   未经校准，桌宠不跟随、不回填。
2. **从「替你写」到「陪你写」**：两档频率升级为三档陪伴——带路（三条完整路线）、提点（只说缺什么，点一下补一句）、同行（关键处才出声）；
   是否退后一步，既看「你烦了没有」，也看「你会了没有」。
3. **从一个时刻到一段路**：路线分主线支线、带下一步；成果回来时提醒先做什么；卡住时问一句；用「你刚发出去的那句话」确认当前聊天；
   可选的本机路书记住项目要点，看得见、改得了、删得掉。
4. **可评估、可长期迭代**：把发起人最初要的「前后测与横评」做回来（评测集、策略对照、练习式前后测）；领域知识做成数据包；
   回填前加一道本机安全闸；盯住「来得及率」——建议必须赶在用户按下发送之前到，否则一切白做。

**路线图**（第 8 节）：M0 立稳与更名 → M1 证据工具链 → M2 陪伴升级 → M3 一段路 → M4 评估与研究 → M5 发布工程。
二代首发（0.3.0）建议只含 M0 + M1 + M2；1.0 这个版本号留给「至少一个 Codex 版本通过真机验收」的那一天。

**需要发起人拍板的事**在第 10 节，共 8 项，其中 3 项会挡住实现：是否同意「未校准不跟随」、旧代码去留、路书是否默认关闭。

## 1. 伴行是什么

**名字**：伴行（Bànxíng，英文写作 Banxing）。伴是在旁边，行是往前走。口号：**你先走，我陪着。**

**给谁用**：想用 AI 做成一件真实的事、但不知道第一句话该怎么说的人——学生、爱好者、第一次用 Codex 的人。

**解决什么**：真实问题多半结构不良。人写下一句模糊的话就发出去，AI 会默默挑一种理解往下做；做出来的东西对不对、下一步是什么，人往往接不住。
伴行不改变「人先行动」这件事，只在三处帮一把：**开口之前**（这句话还能怎么问、还缺什么）、**成果回来之后**（先看什么、先做什么）、
**走偏或卡住的时候**（前面定下的条件漏了、有个岔路没选）。

**和一代的关系**：一代是「开工桌宠」，只管从一句想法到第一份成果这一步。二代把它放进一段更长的陪伴里，并补上发起人最初设想中一代没有做的三件事：
主线与支线、偏好的调整、改造前后的对照评估。

**发起人最初的设想（README 末尾的那段话）在二代里各自落在哪**：

| 最初的设想 | 一代 | 二代 |
| --- | --- | --- |
| 人主动描述问题、目标、哪怕是模糊的想法 | 人先写草稿，桌宠才动 | 不变，并写进底线：开口之前不给模板、不提问题 |
| 结构良好的问题直接读懂 | 没有区分，照样给三条 | 「原样可发」就不出声 |
| 结构不良时搭脚手架：广度、几条脉络、主线支线、让人选 | 三条做法，没有主次 | 三条不同类型的路线，一条主线两条支线，带理由；领域包提供新手常漏的环节 |
| 在读屏的基础上冒泡，有启发性、建议性 | 读输入框与当前聊天，停顿后冒泡 | 再加两个时刻：成果到达、卡住 |
| 一段时间后淡化 | 气泡一直在，直到关掉或失效 | 无人理会一分钟后收成角标；成果到达、卡住的提示自己淡出 |
| 人参考冒泡深入讨论与学习 | 预览全文 | 预览分四段显示提示词的结构；换一批；项目回顾；提点档把写法教给人 |
| 反馈调整能动性 | 两档频率，只看忽略 | 三档陪伴，既看忽略也看是否已经会写 |
| 反馈调整偏好；接受、忽略、扩展讨论都算 | 没有做 | 路线类型的权重；换一批与「要完整路线」作为扩展 |
| 改造前后的对照：不同的 agent、前后测、横评 | 没有做（v0.1 做过） | 策略对照、练习式前后测、评测工具 |

**不变的立场**：

- 人先行动，AI 不先开口提问题，也不替人回答。
- 给选项，不替人选；能回填，但从不发送。
- 拿不准就安静；宁可不出声，不出将就的建议。
- 它学到的关于人的一切，人都看得见、改得了、删得掉。
- 脚手架是要拆的：人越会，它越少。

## 2. 一代复盘

### 2.1 一代做成了什么（事实）

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| 草稿停顿后分析、三重核对、迟到结果丢弃 | `follow.py` | 纯状态机，无 I/O |
| 两档频率与反馈计入 | `frequency.py`、`follow.py` | 忽略多了自动转安静，只由人改回 |
| 一次请求给出是否提示、理由、三条建议；严格校验 | `suggest.py`、`prompts/suggest.md` | 不合格就不显示 |
| 当前聊天：读取、识别、片段提取 | `context/` | App Server 优先，会话文件兜底；认不准就不用 |
| Windows：找窗口和输入框、读、回填、自检 | `platform/` | UI Automation；假设集中在 `profile.py` |
| 设置、同意、密钥绑定、重定向拒绝、本机记录 | `config.py`、`llm.py`、`store.py` | 有专门的安全测试 |
| 桌宠、气泡、预览、菜单、对话框 | `ui/` | Tk；视图模型可单测 |
| 入口与自检 | `cli.py` | 运行、自检、兼容性报告、演示、汇总 |

### 2.2 值得原样保留的

这些是一代最有价值的部分，二代的任何改动都不得削弱（实现者请把它们当作验收条件）：

1. **分层**：规则在纯函数里，线程只在 `controller.py`，界面只画，平台层只和 Windows 说话。
2. **三重核对**：聊天、输入框、草稿三者都没变，才显示、才写入。
3. **从不发送**：全程序只合成 Ctrl+A、Ctrl+V、Delete，有测试扫描源码。
4. **认错聊天比不认更糟**：识别宁可回答「不确定」。
5. **不出将就的气泡**：模型输出不合格 → 出错状态或安静；替身模型从不静默顶替。
6. **发往哪里、同意什么、密钥给谁**：同意绑定实际生效的地址并在发送处复查；密钥绑定服务与接口地址；不跟随重定向；一次尝试一个请求。
7. **本机记录不含内容**：事件日志只收数字、布尔和代码式名字。
8. **测试进沙箱**：任何测试都碰不到真实会话、设置和密钥。
9. **假设即数据**：关于 Codex 的假设集中存放，没在真机上看过的不写「已验证」。

### 2.4 一代的问题清单

以下是带着挑错的眼光重读代码后的发现。标「待真机确认」的，是从代码推断出的风险，没有实测数据。

**产品与规则**

| 编号 | 问题 | 位置 |
| --- | --- | --- |
| P1 | 只有一个时刻（草稿停顿）、一种帮助（整稿替换成我们写的提示词）。用户的原话被改写，久了学不到东西 | `follow.py`、`suggest.py` |
| P2 | 退后一步只看忽略次数。用户草稿已经写得很好时，桌宠仍照常请求模型、照常打扰，直到被忽略四次 | `frequency.py` |
| P3 | 发起人设想里的「偏好」和「扩展讨论」没有做：不记用户常选哪类路线，气泡只有采用和关闭两种回应 | — |
| P4 | 三条建议没有主次，也不说差别在哪。新手凭什么选，没有任何支撑，也没有任何证据 | `ui/viewmodel.py` |
| P5 | 「拿到以后先做什么」只写在内置示例里，模型输出没有这个字段；成果回来时桌宠没有任何动作 | `examples.py`、`suggest.py` |
| P6 | 气泡因切走或继续编辑而收起后，不会自己回来；缓存只在内存、只对同一条消息有效 | `follow.py::_hide_following`、`request_now` |
| P7 | 用户看不到这次建议依据了什么：是否用了聊天片段、用了几轮、是否遮盖过疑似密钥，这些信息算出来了但没有展示 | `suggest.Outcome` 的 `used_context`、`context_turns`、`redacted` |
| P8 | 新聊天里发出第一句话时，输入框清空和聊天标识变化很可能同时发生，这次「原稿被发送」会被记成切换聊天，而不是忽略——恰好是最典型的开工场景。待真机确认 | `follow.py::observe` |
| P9 | 请求发出后不能取消；用户接着改稿，旧请求照样跑完再丢弃，白花一次调用 | `controller._analyze`、`llm.complete` |
| P10 | 停顿 1.5 秒后才开始请求，完整响应还要再等几秒；很多人写完一两秒就发了，这时结果只能丢掉。有多少建议来得及，没有任何数据——这可能是整个产品形态最大的不确定 | `follow.py::result`（`late` 事件） |

## 3. 十三条升级意见

每条写四件事：观点、依据、二代怎么做、代价。

**① 先把一代变成真的：证据先于功能。**
依据：2.3 的表里 E2 以上全空。做法：M0 让 Windows CI 第一次跑绿；M1 做校准向导、证据包、结构录制与回放，把「真机上看到了什么」变成能提交、能回放的数据。
代价：首发里看得见的新功能会少一些。值得——没有证据的功能只是更多的假设。

**② 写之前先校准：未校准不跟随、不回填。**
依据：W9、W3。往别人的输入框里写字是全产品风险最高的动作，现在却是默认行为。做法：首次使用走一遍两三分钟的校准；读稿通过才开启自动跟随，
回填通过才允许一键回填；没通过的机器照样能用粘贴、示例和随叫随到。校准结果按 Codex 版本保存，版本变了重新校准。
代价：首次使用多一步。换来的是每台机器自带一份证据，以及出错时知道错在哪一步。

**③ 从「替你写」到「陪你写」：三档陪伴。**
依据：P1。做法：带路（三条完整路线，等于一代的每稿提示）、提点（只指出这稿缺什么，点一下把那一句补到草稿末尾，原话不动）、同行（等于一代的仅关键时提示）。
提点档的请求短得多、快得多、便宜得多。无论哪一档，草稿已经「原样可发」就不出声（修正 L6）。代价：状态机和界面多一种气泡。

**④ 退后一步，要看「你会了没有」，不只看「你烦了没有」。**
依据：P2；脚手架的本意是随能力增长而撤除。做法：模型在每次分析里顺带判断这稿是否「原样可发」；最近六稿里五稿可发时，桌宠问一句要不要少提示一些——只问，不自动改。
忽略多了仍然自动降一档，并且说一声、可一键改回。往热闹走永远只由人决定。代价：多一个本机计数窗口（只有布尔值）。

**⑤ 路线要分主次、讲差别、带下一步。**
依据：P4、P5；发起人最初的设想里就有主线与支线。做法：三条里恰好一条标为主线并附一句理由，其余是支线；每条带类型（先验证、先做最小版、从现成的改……）、
带「拿到以后先做什么」。类型用于保证三条确实不同，也用于学习偏好。代价：输出字段变多；要防止主线推荐变成变相替人选——所以顺序不因推荐而改变，支线永远在场。

**⑥ 原话由应用拼接，模型只写后半段。**
依据：L3、P1。做法：完整提示词 = 用户草稿原文 + 模型写的三小段（现在做什么、交成什么样、怎么检查）。原话一字不改由应用保证，预览里三段分开显示。
省输出、杜绝改写用户意思，还顺带把「好提示词长什么样」教给了用户。代价：有一类情况原话不能照做——用户说「全部导入」，而前面的重复项还没处理。
直接把原话放在开头，Codex 可能先照做再看后半段。所以每条路线带一个「先缓一缓」标记：标了的，应用把原话放进引号并注明先不要照这句做（4.4）。

**⑦ 从一个时刻到一段路。**
依据：P5、P6。做法：新增两个不需要模型的时刻——成果到达（用户发出了采纳的路线、这一轮结束时，桌宠淡淡地提醒一句当初那条路线的「下一步」）、
卡住（同一条消息大改三次还没发出去，提点或同行档下桌宠问一句要不要帮忙）。再加一个按需的时刻：回顾。代价：需要可靠地知道「这一轮结束了」，这一点待真机确认，拿不到就不做。

**⑧ 用「你刚发出去的那句话」确认当前聊天。**
依据：W5、P8；现在靠窗口里看得见的文字去猜。做法：桌宠看着草稿被发出去；几秒后，会话数据里恰好有一个聊天的最新用户消息等于这句话——这个聊天就是眼前这个。
此后只要聊天标识不变就不用再猜。同一机制顺便确认了「原稿被发送」，补上 P8。代价：只对用户在桌宠运行期间发过消息的聊天有效，其余仍走可见文字匹配。

**⑨ 记得住，但记的东西看得见、删得掉。**
依据：一代只看最近三轮，十轮前定下的条件就丢了；偏好也没记。做法：路书（每个聊天一份：目标、定下的条件、悬着的事、选了哪条路、搁置的支线）
和「关于我」（常驻的事实与偏好）。两者都只在本机，可在窗口里逐条查看、修改、删除；持久保存默认关闭，由用户打开。代价：第一次引入「本机保存与内容有关的东西」，隐私设计要重做一遍（第 5 节）。

**⑩ 把一键回填当成有风险的动作来设防。**
依据：L5、W3、W4。做法：回填前过一道本机安全闸——草稿和聊天里都没有出现过的外部地址、明显的外泄写法，直接丢弃该条；要求提权的、
有破坏性操作却没有预览或备份的，标出警示并要求先看预览再填。另外：密码框一律不读；粘贴用的临时内容不进剪贴板历史（待查证接口）；遮盖过疑似密钥时在气泡里明说。代价：会有误拦，需要评测集调校。

**⑪ 把「前后测与横评」做回来。**
依据：发起人最初的要求；v0.1 做过，一代丢了。做法：评测工具（场景集 × 策略 × 模型，结构检查加裁判模型打分，可导出给人盲评）；
策略做成可切换的单元，便于对照（三条路线、只补一句、只改写一条、只问一个问题）；研究模式下的练习式前后测。代价：研究模式会保存用户的作答，必须单独知情同意。

**⑫ 不绑死在一个窗口上：随叫随到。**
依据：自动跟随依赖对某个应用的逐版本适配，而这一层目前是 E0。做法：全局热键对「当前选中的文字」给建议，选一条替换选区或复制。任何应用都能用，
也是自动跟随失效时的退路。代价：又多一段需要在 Windows 上验证的代码；放在 M3。

**⑬ 盯住「来得及率」：建议要赶在按下发送之前到。**
依据：P10、P9、L4。到底有多少建议来得及，一代没有数据。做法：把来得及率（显示出来的次数 ÷ 显示与迟到之和）列为头号指标；用提点档和流式提速；
改稿即取消旧请求；迟到、但那句话确实已经发出去了的路线不丢，留在桌宠上作为「刚才那句还可以这样问」的备选，点了才看；服务连续失败时暂停自动请求。
如果试用里来得及率长期低于一半，说明「停顿之后才开始想」这个时机本身不合适，产品重心就要移到成果回来之后（下一句怎么接）。这要用数据回答，现在定不了。
代价：多一个内存里的备选缓存；可能要面对一个不讨喜的结论。

另有一条贯穿性的工程意见：**领域知识做成数据包**（检查清单、示例、评测场景放在一起），发起人不写代码也能加一个领域（4.12）。

## 4. 二代产品设计

### 4.1 底线

2.2 的九条全部保留。二代新增四条：

10. **未校准不跟随、不回填。** 自动读取和写入只在本机校准通过后开启，并且只对通过校准的那个 Codex 版本有效。
11. **往安静走可以自动，往热闹走只由人决定。** 自动的每一步都说一声，并且可以一键改回。
12. **原话不动。** 填进输入框的文字里，用户自己的话由应用原样放回，模型不得改写。
13. **与内容有关的东西，不开不存。** 路书、关于我、研究模式的作答，默认只在内存里；写到磁盘必须由用户打开，并且看得见、删得掉。

### 4.2 三档陪伴

| 档 | 桌宠做什么 | 一次请求要模型给什么 | 适合 |
| --- | --- | --- | --- |
| **带路** | 每份还不能原样发的草稿都给三条路线，选一条填入 | 是否可发、三条路线 | 刚开始用；一件事不知从哪下手 |
| **提点** | 只说这稿还缺什么（最多三处），点一下补一句 | 是否可发、缺什么 | 已经有感觉，想自己写 |
| **同行** | 平时不出声；只有说得出具体问题时才提醒，并给三条路线 | 是否可发、是否提醒、理由、三条路线 | 熟手；长项目中段 |

- 新用户从带路开始。菜单「陪伴方式」随时可改。
- 任何一档下，点一下桌宠都能立刻要三条完整路线。
- 从一代迁移：每稿提示 → 带路；仅关键时提示 → 同行。

**「原样可发」的定义**（三档共用，也是渐退与北极星指标的基础）：这句话不改就发出去，Codex 不必猜任何关键的东西就能做出用户要的那份成果——
要做什么、交成什么样、怎么算对，要么草稿里写明了，要么从这个聊天的上文里看得出来。上一轮已经有了页面，这一轮只说「把标题改成深蓝色」，是原样可发；
开头一句「想做个记账的小工具」，不是。**三档里，原样可发的草稿一律不出气泡**，桌宠只短暂显示一个对勾。

不是在请 Codex 做事的草稿（寒暄、道谢、随口一问）单独标记为「非任务」：不出气泡，也不计入任何统计。

这个判断由模型做，会出错。它的准确度是评测集里的一项硬指标（7.6）；达不到门槛的模型，在配置页提示「这个模型判断不稳，建议只用带路档并手动控制」。

### 4.3 渐退规则

状态（纯数据，只有枚举、计数和布尔值，可写入本机状态文件）：当前档位、是谁设的、当前档位下最近 6 次计入的反馈、最近 6 份自动分析过的草稿是否「原样可发」、上次询问的时间。

| 规则 | 条件 | 动作 |
| --- | --- | --- |
| A 嫌打扰 | 当前档最近 6 次计入的反馈里 4 次是忽略 | 自动降一档（带路→提点→同行）；提示一句并带「改回去」 |
| B 已经会了 | 带路或提点档，最近 6 份分析过的草稿里 5 份原样可发 | 只问一句「最近的草稿都挺完整，要不要少提示一些？」；同意才降档；拒绝后 7 天内不再问 |
| C 卡住了 | 见 4.6 | 只问一句要不要帮忙；不改档位 |
| D 人说了算 | 用户在菜单里选了某一档 | 立即生效，清空两个观察窗口 |

同行档没有任何自动出口。规则 A 触发后用户点了「改回去」，等同于规则 D。

**反馈怎样计入**（沿用一代的定义，扩展到提点气泡）：

| 气泡 | 采用 | 忽略 | 不计入 |
| --- | --- | --- | --- |
| 路线（自动出现） | 选了一条并填入成功；或复制了一条 | 关掉；或显示满 2 秒后原稿被发出 | 没看完就失效：接着改稿、切走、结果迟到、不足 2 秒就发 |
| 提点（自动出现） | 至少补了一句；或点了「要三条完整路线」 | 同上 | 同上 |
| 点桌宠要来的 | 计入采用 | 关掉不算忽略——关掉自己要来的东西不代表嫌打扰 | — |
| 粘贴草稿、内置示例、随叫随到、迟到的备选 | — | — | 全部不计入：它们不是桌宠主动出声 |

每条消息最多计一次；忽略之后又采用，改记为采用；撤回回填则取消采用。

### 4.4 路线卡（带路与同行档）

每条路线的字段：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `approach` | 路线名 | 动词开头，8 个汉字以内 |
| `deliverable` | 第一份成果 | 名词短语，14 个汉字以内 |
| `kind` | 路线类型 | `verify` 先验证 · `minimal` 先做最小版 · `adapt` 从现成的改 · `delegate` 交给别人或现成工具 · `prototype` 先做看得见的样子 · `plan` 先定规则 · `other` |
| `main` | 是否主线 | 三条里恰好一条为真 |
| `why` | 为什么推荐它 | 仅主线需要，20 个汉字以内，必须是对当前情况的陈述（如「你还没量过地方」） |
| `fits` | 什么情况下选它 | 一句 |
| `do` / `deliver` / `check` | 提示词后半段的三小段：现在做哪一步、交成什么样、拿到怎么检查 | 各一到两句；不得反问用户 |
| `hold` | 先缓一缓：草稿里的那句话不该原样照做（典型是同行档的关键提醒） | 布尔值，默认假 |
| `next` | 拿到成果后先做什么 | 一句；用于成果到达提示 |

**完整提示词由应用生成**，草稿原文逐字保留：

- `hold` 为假：`草稿原文（补上句末标点）+ do + deliver + check`。
- `hold` 为真：`我本来想这样说：「草稿原文」先不要照这句话做。+ do + deliver + check`。引导语是应用里的固定文案（中英各一），不由模型写。

应用侧校验（任何一条不过，整个气泡不显示，进入出错状态并可重试）：恰好三条；路线名互不相同；三条里至少两种类型；恰好一条主线且带理由；
后半段两两相似度低于 0.92；每条通过安全闸（第 5 节）；同行档必须带理由。

气泡的样子（文字示意）：

```
三条路线 · 选一条填入 Codex                                  ×
主线  先做纸样比一比    拿到能打印的等大纸样        预览
      因为：你还没量过阳台
支线  先做单层练手      拿到单层的图纸和材料单      预览
支线  买现成的来改      拿到改装步骤和采购清单      预览
依据：草稿 + 这个聊天最近 3 轮                         换一批
```

- 顺序就是模型给的顺序，不因主线标记而调整；主线不加粗、不置顶，只多一个标签和一行理由。
- 预览里把提示词分四段显示：你的原话 / 现在做什么 / 交成什么样 / 怎么检查，各带小标签；下面是「填入 Codex」「复制」。
- 「依据」一行可点开，看到这次实际发给模型的内容（只在内存里，关掉气泡就没有了）。遮盖过疑似密钥时，这一行写「已隐去 N 处疑似密钥」。
- 「换一批」每份草稿最多一次，请求里带上已经给过的三个路线名，要求不重复。它本身不计入采用或忽略；换出来的气泡仍属于同一条消息。
  日志里记一次 `more`，用来观察第一批是否经常不合用。这是发起人设想里「扩展讨论」的最小形态；预览里的「为什么推荐这条」同理。
- **迟到的路线不丢**：结果回来时那句话已经发出去了（经 4.8 确认，或输入框在同一聊天里由该草稿一步变空），这三条路线在内存里留十分钟，
  桌宠上出现一个小角标；点开的标题是「刚才那句还可以这样问」。用户没点就自己过期，不计入任何反馈。

### 4.5 「补一句」（提点档）

模型返回这稿缺的东西，最多三处。每处是下面两种之一：

| 形式 | 含义 | 点了以后 |
| --- | --- | --- |
| 补句 `clause` | 一句可以直接接在草稿后面的话，例如「请做成双击就能打开的网页。」 | 草稿末尾追加这一句 |
| 提问 `ask` | 只有用户自己知道的事，例如「阳台量过了吗？」 | 草稿末尾追加一个待填的开头，例如「阳台的尺寸：」，光标留在后面 |

每处还有 `kind`（成果形式、怎么检查、已知条件、范围、缺的数据）和不超过 10 个汉字的 `label`。

规则：

- 模型不得改写草稿；补句必须是接在原话后面读得通的一句完整的话。
- 补一句走的是和回填同一条路：先三重核对，再把「当前草稿 + 这一句」写回去。写入成功后，气泡留在原处，剩下的条目仍可点；
  气泡记住的草稿换成新的文本，这段新文本不再触发分析。
- 「恢复原草稿」一次撤掉本条消息里补过的所有句子，回到用户最初的那一稿。
- 用户自己动了草稿，气泡照常收起。
- 气泡底部有「要三条完整路线」。

### 4.6 时刻

| 时刻 | 触发 | 桌宠做什么 | 需要模型 | 需要的能力 |
| --- | --- | --- | --- | --- |
| 开口之前 | 草稿停顿（一代已有） | 按当前档位出路线或提点 | 是 | 读稿 |
| 接着往下做 | 同上，同行档 | 说得出具体问题才提醒 | 是 | 读稿；认聊天更好 |
| 成果到达 | 用户发出了采纳的那条路线，并且这一轮结束 | 在桌宠旁显示一句会自己淡掉的话：「成果到了，先做：……」，内容是那条路线的 `next` | 否 | 知道发送、知道轮次结束 |
| 卡住 | 同一条消息有三次实质改动仍未发出，且当前不是带路档 | 问一句「要不要换个问法？」，点了才请求模型 | 点了才是 | 读稿 |
| 回顾（按需） | 菜单「回顾这个项目」 | 一屏：目标、走过的路线、定下的条件、悬着的事、下次可以怎么开口 | 是 | 路书 |

- 成果到达和卡住的提示都算「淡出式」：十几秒后自己消失，消失不记为忽略。
- 路线与提点气泡显示一分钟无人理会（鼠标没有移上去过），自动收成桌宠上的一个角标，点桌宠即展开。收起本身不计入反馈；
  之后原稿被发出，仍按「显示满 2 秒后发出原稿」记为忽略。
- 「知道轮次结束」的来源待真机确认（会话数据里的完成标记，或界面状态）。拿不到这个能力，成果到达这个时刻就不出现，不用别的办法猜。
- 气泡被动收起（切走、聊天切换）后，如果十分钟内回到同一聊天且草稿没变，气泡在桌宠上留一个小角标，点桌宠即回来。这不是新提示，不重复计入。

### 4.7 路书与「关于我」

**路书**——一个聊天一份：

| 条目 | 来源 | 何时有 |
| --- | --- | --- |
| 选了哪条路线、它的下一步；搁置的支线（只有名字和成果） | 桌宠自己的事件 | M3 起，内存中总是有 |
| 目标一句话、定下的条件、悬着的事、已经交付的成果 | 模型在每次分析时顺带提炼 | M3 后期，需用户打开 |

- 路书只绑定到**已确认身份**的聊天（4.8）。身份不确定就没有路书。
- 路书随请求发给模型，替代「只看最近三轮」的短记忆：十轮前定下的条件不再丢。
- 「路书」窗口逐条列出，每条可改可删；气泡的「依据」一行会写「路书 N 条」。
- 默认只在内存里，退出即失。用户打开「记住这个项目」后才写盘：加密保存，30 天不活动自动删除，最多保留 20 份。
- 模型提炼的内容可能出错。任何一条被用户删掉后，同一聊天里不再自动加回相同内容。

**关于我**——常驻、与具体项目无关：

- 用户自己写的事实（例如「我没有编程基础」「我用 Windows」「家里没有电钻」），随每次请求发出，三条路线都要遵守。
- 路线类型的偏好：每种类型一个权重，采用加、忽略减，有下限（任何类型都不会归零——口味会变）。只用于两件事：主线推荐时的平手裁决、「换一批」时的倾向。
  **不**用于减少多样性，三条里至少两种类型的规则不变。
- 窗口里看得到权重的大致高低（三档：常选、一般、少选），可以一键清零。

### 4.8 认聊天：发送指纹绑定

现有做法（保留，作为第二手段）：用窗口里看得见的文字匹配最近的会话。

新增第一手段：

1. 上一眼某个输入框里还是草稿 D，这一眼 D 不在了——输入框空了，或者聊天标识变了。状态机把 D 记为「可能刚被发出」：指纹、时间、窗口，只在内存里。
2. 接下来 30 秒内，上下文模块查看最近更新的会话：如果**恰好一个**会话的最新用户消息与 D 相同，并且 D 的开头此刻就显示在窗口文字的末段，
   就把「这个窗口此刻的聊天标识」绑定到这个会话。
3. 绑定在聊天标识变化前一直有效；标识变了就作废，等下一次发送再绑。
4. 第 2 步成立的同时，通知状态机「D 确实被发出去了」。如果 D 对应的气泡刚才因为聊天标识变化被当作切换收起，这时改按「原稿被发送」处理（显示满 2 秒则记忽略）。

要点：不成立就什么都不做；两个会话都匹配就不绑；指纹和开头只在内存里，不写日志。

### 4.9 随叫随到

- 一个全局热键（可改，可关）。按下时：读当前焦点控件里**选中的文字**；没有选区而控件是普通多行输入框时，读全文；密码框一律不读。
- 气泡出现在光标附近，内容与带路档相同（不带聊天片段，除非当前窗口就是已校准的 Codex）。
- 选一条：焦点仍在原控件、选区没变，则用粘贴替换选区；否则复制。三重核对在这里是：窗口、控件、选中文字。
- 读不到选区时不代替用户按复制键；菜单里另有「用剪贴板里的文字」。
- 全部待真机验证；放在 M3。

### 4.10 等待与花费

- **提点档天然更快**：输出只有几十到一两百字。
- **流式**：响应改成一行一个 JSON 对象（6.4）。带路档先到三行标题，气泡立即出现三行；后半段陆续到。点了后半段还没到的行，等它到了再填（到时重新做三重核对）。
- **改稿即取消**：草稿有实质变化时关闭正在进行的连接，不再等它跑完。
- **不重试**的规则不变：一次尝试一个请求；失败给出状态和重试入口。
- **连续失败就停**：十分钟内连续三次自动请求失败，自动请求暂停，桌宠显示原因；用户点重试成功一次后恢复。不让一个坏掉的服务被每份草稿反复敲打。
- **用量可见**：本机累计当天请求次数与模型返回的用量数字（只有数字）；每日上限默认 300 次，可改；达到上限后只响应用户主动要的请求。
- **本机模型**：一代已经支持把兼容接口指向本机地址；二代在模型配置里把它列为一个明确的选项（「草稿不出这台电脑」），质量同样要过评测。
- 是否使用服务端的提示词缓存、结构化输出，取决于各服务的实际接口，待查证后再定；不作为首发条件。

### 4.11 界面与首次使用

首次使用四步：欢迎与三句承诺（不替你发送、数据在本机、随时可关）→ 模型配置与发往哪里 → 校准（可跳过，跳过则只有粘贴、示例、随叫随到）→ 用内置示例在练习框里走一遍。

桌宠状态：待机、生成中、暂停、出错、需要处理（未配置、未校准、读不到）、成果到达。右键菜单第一行永远是当前状态的一句话。

菜单（按使用频率排）：陪伴方式 ▸；暂停或继续；现在给三条路线；重试；恢复原草稿；路书…；关于我…；粘贴草稿…；内置示例 ▸；
模型配置…；校准与自检…；今日用量；打开数据文件夹；清除本机数据…；关于；退出。

无障碍与键盘：气泡出现时可用可配置的热键选第一、二、三条或关闭（与随叫随到的热键一起做，M3）；字号跟随系统缩放，另有大字选项。

界面技术栈维持 Tk（理由与重议条件见 6.6）。

### 4.12 领域包

一个领域一个文件夹，全是数据，没有代码：

| 文件 | 内容 |
| --- | --- |
| `pack.json` | 标识、中英文名称、触发词、新手常漏的环节（只给模型当思考提示，不展示给用户）、这个领域里常见的路线类型 |
| `examples.json` | 一到两组内置示例（草稿、三条路线），既是菜单里的示例，也是替身模型和测试的夹具 |
| `scenarios.json` | 这个领域的评测场景与标注 |

- 随程序发布的包在程序目录里；用户自己的包放在数据目录的 `packs/` 下，同名时用户的优先。
- 加载时逐字段校验，不合格的包整个跳过并在自检里报告；包里的文字只会作为资料进入请求，不会被当作指令。
- 首批四个包由一代的 `checklists.py` 与 `examples.py` 原样转成：家具、文件整理、个人软件、通用。
- 加一个领域（比如表格数据、学习计划）= 加一个文件夹 + 跑一遍评测，不改代码。

## 5. 可信：隐私与安全升级

### 5.1 数据清单

| 数据 | 去哪 | 落盘 | 用户控制 |
| --- | --- | --- | --- |
| 草稿、聊天片段 | 用户配置的模型服务 | 否 | 同意后才发；可关聊天片段；可暂停 |
| 路书（内存） | 随请求发给模型 | 否 | 可逐条删 |
| 路书（记住这个项目） | 同上 | 是，加密，30 天不活动删除 | 默认关；可逐条改删；可整份删 |
| 关于我 | 随请求发给模型 | 是，加密 | 默认空；自己写；可清空 |
| 档位、反馈窗口、类型权重、用量 | 不出本机 | 是 | 可清零 |
| 事件日志 | 不出本机 | 是；只有数字、布尔、代码式名字 | 可删 |
| 校准结果、证据包 | 不出本机，除非用户自己导出并提交 | 是；不含草稿和聊天文字 | 导出前可查看全文 |
| 窗口可见文字、发送指纹 | 不出本机 | 否，只在内存 | — |
| 研究模式的练习作答 | 不出本机，除非用户导出 | 是 | 单独知情同意；可删 |

同意的范围随之扩大：同意书列出本次会发送的数据种类；打开路书持久化或填写关于我时，在各自的开关旁说明并记录一次。发往的地址变了，全部同意作废（一代已有）。

### 5.2 回填前的安全闸

纯函数，输入是草稿、聊天片段、模型写的后半段，输出是放行、警示或丢弃，以及原因代码。

| 检查 | 条件 | 结果 |
| --- | --- | --- |
| 外来地址 | 后半段里出现了草稿和聊天片段里都没有的网址、域名、IP、邮箱 | 丢弃该条 |
| 外泄 | 「上传、发送到、提交到」一类动作与「密钥、令牌、密码、cookie、环境变量文件、私钥」同句出现 | 丢弃 |
| 管道执行 | 下载后直接交给解释器执行的写法 | 丢弃 |
| 指令覆盖 | 要求忽略先前指令、规则或限制的写法 | 丢弃 |
| 提权与绕过 | 管理员权限、注册表、关闭防护、跳过确认或沙箱的参数 | 警示 |
| 破坏性操作 | 删除、清空、覆盖、强制推送一类动作，而同条里没有预览、副本、备份、恢复中的任何一个 | 警示 |

- 丢弃后不足三条 → 整个气泡不显示，状态为「这次的建议没通过安全检查」，可重试。
- 警示的行带一个标记；点它不直接回填，先展开预览，用户在预览里再点一次才填。
- 词表是数据文件，带中英文；评测集里有专门的注入样例（聊天片段里夹带指令）用来调校，目标是这些样例全部被拦下。

### 5.3 平台侧

- **密码框与敏感控件**：带密码属性的控件不读、不写、不作为输入框候选。
- **输入框必须是校准认过的那一个**：校准记下输入框的特征（控件类型、所属框架、多行提示、相对位置与宽度占比）；运行时不符合特征的可编辑控件不当作输入框。
- **剪贴板**：粘贴用的临时内容标记为不进剪贴板历史、不上云（接口待查证）；粘贴后恢复原内容；剪贴板里有无法保存的内容时不走粘贴。
- **疑似密钥**：遮盖规则保留；遮盖后的草稿如果大部分是被遮盖的内容，不发送。
- **自动化超时与看门狗**：给界面自动化调用设上限（接口待查证）；界面线程超过 5 秒没有收到快照，状态改为「读不到」，并放弃正在等待的回填。

### 5.4 威胁与对策一览

| 威胁 | 对策 |
| --- | --- |
| 聊天内容夹带指令，诱导生成危险提示词 | 资料与指令分开的提示词（已有）；安全闸；原话不动；警示行两步回填 |
| 读到不该读的输入框 | 未校准不跟随；密码框排除；特征匹配 |
| 写到不该写的地方 | 三重核对（已有）；未校准不回填；只对校准过的版本回填 |
| 密钥或草稿被发到别处 | 已有：地址同意、密钥绑定、不跟随重定向、单次请求 |
| 本机文件泄露用户内容 | 与内容有关的默认不落盘；落盘的加密、限期、可删；日志只收代码式名字 |
| 认错聊天，引用了别的项目 | 发送指纹绑定；可见文字匹配保持保守；不确定就不用 |
| 更新渠道被冒用 | 首发不做自动更新；只提示有新版本并指向发布页；签名见 M5 |

### 6.2 关键接口

```python
class HostClient:                      # 取代 CodexClient
    name: str
    def capabilities(self) -> frozenset:   # {"read", "fill", "chat_key", "signals", "turn_events", "selection"}
    def snapshot(self, now) -> Snapshot
    def signals(self) -> ChatSignals | None
    def fill(self, key, expect, text) -> FillResult
    def probe(self, try_fill=False) -> dict
```

- 状态机不再看 `fill_supported` 这样的布尔值，而是看能力集合；能力集合 = 平台能做的 ∩ 校准通过的。

| 能力 | 来自校准的哪一步 | 没有它时 |
| --- | --- | --- |
| `read` 读稿 | C1–C4 | 不自动分析；状态显示原因；粘贴、示例、随叫随到照常 |
| `fill` 写入 | C5、C6 | 选一条 = 复制，补一句 = 复制这一句；气泡标题随之改变 |
| `chat_key` 聊天标识 | C7 | 不做发送指纹绑定，不建路书；可见文字匹配仍可用（每次分析都重新取窗口文字） |
| `signals` 窗口文字 | C2、C9 | 不用聊天片段，只看草稿 |
| `turn_events` 轮次结束 | C8 | 没有成果到达这个时刻 |
| `selection` 选区 | M3 的单独校准 | 随叫随到只能用剪贴板里的文字 |
- `Strategy`：`build(request) -> (system, user)`、`parse(lines) -> Outcome`、`mock(request) -> str`。每个策略必须有替身分支，测试保持离线。
- `Outcome` 增加：`task`、`ready`、`missing`、`assumes`、`strategy`、`prompt_version`、`usage`；`Suggestion` 更名为 `Route` 并换成 4.4 的字段，`prompt` 改为由应用拼接的只读属性。
- 状态机的气泡多一个 `kind`：`routes`、`hints`、`note`。效果（effects）列表不变，新增 `Sent`（内存内，供绑定用）和 `Ask`（规则 B、C 的询问）。
- `Controller` 仍然只接线。校准向导的步骤逻辑放在纯模块里，界面只负责显示每一步。

### 6.3 数据与迁移

- `settings.json`、`state.json` 各带 `schema` 版本号；迁移函数只追加、不修改已有条目（沿用 v0.1 的做法）。
- 一代 → 二代：`frequency.mode` 的 `every`/`critical` 映射为 `lead`/`walk`；反馈窗口清空。
- 数据目录由 `AI-Collaborator` 改为 `Banxing`。**如果 0.2.0 在二代之前没有公开发布，就不做目录迁移**；发布过，则首次启动时把旧目录里的设置与状态复制过来。
  密钥是用旧的附加熵加密的，迁移时用旧熵解开、用新熵重新加密；解不开就请用户重新输入。
- 事件日志增加字段：`level`、`strategy`、`prompt_version`、`host`、`bubble`（种类）。仍然只收数字、布尔和代码式名字。
- 新文件：`calibration.json`（按 Codex 版本）、`vault/`（加密的路书与关于我）、`usage.json`（按天的计数）。

### 6.4 响应格式 v2

请求里的 `<mode>`：`lead`、`hint`、`walk`；用户主动要时加 `pull`，此时必须给路线。另有 `<about>`（关于我）、`<trail>`（路书）、`<given>`（换一批时已给过的路线名）。

响应是若干行，每行一个 JSON 对象，按这个顺序：

```
{"v": 2, "task": true, "ready": false, "show": true, "reason": "", "pack": "furniture", "assumes": "还没量过阳台"}
{"missing": [{"kind": "deliverable", "label": "没说要什么样的成果", "clause": "请做成双击就能打开的网页。"}]}
{"route": 0, "approach": "…", "deliverable": "…", "kind": "verify", "main": true, "why": "…", "hold": false}
{"route": 1, …}
{"route": 2, …}
{"route": 0, "fits": "…", "do": "…", "deliver": "…", "check": "…", "next": "…"}
{"route": 1, …}
{"route": 2, …}
```

- 第一行永远有。`task` 为假、`ready` 为真（且不是用户主动要的）、或 `show` 为假时，只有第一行。
- `hint` 模式只有前两行；`lead`、`walk` 模式没有第二行。
- `show` 的含义按模式：`lead` 与 `hint` 下等于「是任务且还不能原样发」；`walk` 下还要求说得出具体问题，并把它写进 `reason`。
- 不支持流式的服务：整段收到后按行解析，结果相同。
- 解析对多余的空行、代码块围栏宽容；对缺行、重复 `route`、未知 `kind` 按 4.4 的校验处理。旧的单对象格式不再接受。
- 每个提示词文件的第一行是版本号；改了提示词就必须改版本号（有测试比对文件内容的摘要与版本号的登记表）。版本号进事件日志和评测报告。

### 6.6 几个技术决定

| 决定 | 选择 | 理由 | 什么时候重议 |
| --- | --- | --- | --- |
| 语言与界面 | 继续 Python + Tk | 核心可在 Linux 上测试；无额外运行时；实现者没有 Windows，换成需要在 Windows 上编译的技术栈等于闭眼写 | 真机证明 Tk 的非激活浮窗做不到不抢焦点时，只替换外壳（`View` 接口已隔离） |
| 轮询还是事件 | 继续轮询，但分层降频：打字时快、静止时慢、Codex 不在前台时几乎不查；全树查找改为按需 | 事件订阅涉及跨线程回调，在没有真机的情况下风险更大 | M1 的性能自测显示轮询开销不可接受时 |
| 读聊天的首选来源 | 维持现有顺序，但由校准结果决定本机实际使用哪一个 | 两条路径对真实数据都是 E0 | 拿到 E3 证据后按证据定默认 |
| 依赖 | 核心仍只用标准库；Windows 运行时仍是 comtypes（必需）、pystray 与 Pillow（可选） | 少一个依赖少一份打包风险 | 新增任何依赖前先问 |
| 截图与看图识别 | 不做 | 隐私代价高；与「不确定就安静」相悖 | 三代再议 |

## 7. 证据与验证

### 7.1 用语

文档、发布说明、提交信息里只用下面这些说法，并且总是带上等级：

- 「离线通过（E1）」「Windows 机器通过（E2）」「真机通过（E3，Codex 版本 x，日期，证据编号）」「真模型评测（E4，模型 x，提示词版本 y）」「试用结论（E5）」。
- 不单独使用「已验证」「测试通过」「可用」这样的词。
- 替身模型的任何结果只能写作「流程走通」，不能出现在质量结论里。

### 7.2 证据台账

`docs/verification.md` 改成台账：每一行是一个检查项，有固定编号（8.2 的工作包会引用），列出当前最高证据等级和指向 `docs/evidence/` 下具体记录的链接。
每份记录一个文件，写明日期、执行人、机器与系统版本、Codex 版本、伴行版本、逐项结果与数字。模板见附录 E。

### 7.3 校准向导

向导让用户在自己的 Codex 上做九个小动作。向导知道每一步「应该读到什么」（校准用的固定短语），因此可以判断对错而**不需要保存用户的任何文字**。

| 步骤 | 用户做什么 | 记录什么 | 决定什么 |
| --- | --- | --- | --- |
| C1 认窗口 | 点一下 Codex 窗口 | 进程名、窗口类名 | 跟随哪个进程 |
| C2 认输入框、读稿 | 点进输入框，输入校准短语 | 控件类型、框架、可用接口、是否密码框、位置与宽度占比；读到的内容是否等于校准短语 | 能力「读」；输入框特征 |
| C3 空输入框 | 清空 | 此时读到的文字（这是应用界面的占位文字，不是用户内容） | 占位文字表 |
| C4 输入法 | 用输入法打一句中文，选词时停两秒 | 选词期间出现了哪些信号（候选窗口类名、文本是否变化、编辑器是否报告正在组合） | 输入法判断方式 |
| C5 回填 | 等待即可 | 两种写入方式各自：是否成功、读回是否一致、耗时、焦点是否回到输入框、剪贴板是否复原；最后原稿是否还在 | 能力「写」及首选方式 |
| C6 焦点 | 点一下测试气泡，然后直接打一个字 | 那个字是否进了输入框 | 浮窗是否不抢焦点 |
| C7 聊天标识 | 切到另一个聊天再切回来 | 标识是否变化、是否回到原值、来源是地址还是标题 | 能力「聊天标识」 |
| C8 会话数据 | 等待即可 | 两条读取路径各自能否握手或解析、字段是否齐全、有多少会话与轮次（只有数量） | 读聊天用哪条路径 |
| C9 性能 | 等待十秒 | 快照耗时的中位数与 95 分位、取窗口文字的耗时、这十秒里 Codex 进程的 CPU 占用与校准前十秒的差 | 轮询频率；是否需要降级 |

向导结束时给出一页结果：哪些能力开了、哪些没开、为什么。结果写入 `calibration.json`，按 Codex 版本保存。

### 7.4 证据包与结构录制

- **证据包**：一个 zip，内含自检结果、校准结果、兼容性报告、系统与 Codex 版本、缩放比例、已安装的输入法列表。全部是 JSON 和纯文本，
  导出前在窗口里完整显示，用户确认后保存到自己选的位置。伴行不上传任何东西。
- **结构录制**：把输入框周围的界面结构记下来——每个节点只记类型、框架、类名、可用接口、是否密码框、相对位置和大小、文字的**长度**——不记任何文字。
  录制文件放进仓库的测试夹具后，`hosts/replay.py` 可以把它当成一个假的宿主回放，于是「真机上的界面长什么样」变成了能在 Linux 上跑的回归测试。
- 每次有人提交证据包，对应的结构录制进夹具、台账加一行。这是把 E3 证据沉淀成 E1 测试的唯一通道。

### 7.5 真机验收 v2（计数标准）

在通过校准的机器上，由人按下表操作并计数。数字是首轮的假定门槛，第一次实测后按实际情况修订，修订要写进台账。

| 编号 | 检查 | 做法 | 通过 |
| --- | --- | --- | --- |
| A1 | 读稿准确 | 20 段不同的草稿：多行、中英混排、带符号 | 20 次都与所见一致（人工比对，不留存文字） |
| A2 | 停顿触发 | 20 次写完停手 | 20 次都在 1 到 2 秒内进入生成中 |
| A3 | 输入法 | 用拼音打 30 句，每句选词时故意停两秒 | 选词期间触发分析 0 次 |
| A4 | 回填 | 30 次选一条 | 内容一致 30；未被发送 30；光标在输入框 30；剪贴板复原 30 |
| A5 | 不抢焦点 | 点气泡或桌宠后直接打字，30 次 | 字进入 Codex 30 |
| A6 | 聊天切换 | 两个聊天来回切 20 次，各有草稿 | 旧气泡每次都收起；迟到结果显示在错误聊天里 0 次 |
| A7 | 认聊天 | 在 5 个不同的聊天里各发一句再写草稿 | 绑定正确 5；任何时候绑定到错误会话 0 次（「不确定」不算错） |
| A8 | 补一句 | 提点档下 20 次补句，其中 5 次连补两句 | 草稿 = 原话 + 所补句子，逐字一致 20；恢复原草稿成功 5 |
| A9 | 安全 | 设置页的输入框、登录框里打字并停顿 | 触发分析 0 次 |
| A10 | 性能 | 开着伴行正常使用 30 分钟 | 伴行进程 CPU 空闲时低于 1%、打字时低于 3%；Codex 进程 CPU 与不开伴行时相比差不超过 2 个百分点 |
| A11 | 稳定 | 连续运行 8 小时 | 无崩溃；内存增长不超过 30 MB |
| A12 | 成果到达 | 采纳并发送 10 次 | 轮次结束后 10 秒内出现提示 10；没结束就出现 0 |

A1–A6、A9–A11 针对基本回路，是 1.0 的门槛；A8 随 M2 的补一句；A7、A12 随 M3。

任何一项里出现「发送了用户没有发送的东西」「写进了错误的输入框」「引用了错误聊天的内容」，无论次数，该版本的对应能力直接关闭。

### 7.6 模型质量评测（E4）

评测工具离线可跑；要产出 E4 证据需要一把模型密钥，由发起人或协调方执行。

- **场景集**：每个场景有草稿、可选的聊天片段、模式、标注（是不是任务；是否原样可发；应不应该出声；必须保留的条件；不该出现的东西）。首批不少于 50 个：
  三个领域包各 8 个、通用 6 个、原样可发与否 10 个（各半）、关键情况 10 个（一半该出声、一半不该）、注入样例 10 个；其中至少 6 个是英文草稿。
  场景文字全部新写，不取自发起人的原始方案。
- **结构检查**（不需要裁判）：格式、恰好三条、类型多样、主线唯一、条件保留（按标注的关键词）、缺数据时是否标明示例、有没有反问用户、安全闸结果、
  补句是否能直接接在原话后面。
- **裁判打分**（另一个模型，0 到 4 分）：能不能直接开工、三条是否真不同、第一份成果能不能检查、假设与待确认是否交代、是否尊重条件、新手看不看得懂。
- **人工盲评**：导出打乱且匿名的表格给人打分，再导回来与裁判对照，算一致程度。
- **首轮假定门槛**：结构合格不低于 95%；条件保留不低于 95%；「原样可发」的判断与标注一致不低于 85%，其中把还不能发的判成可发的不超过 10%；
  关键情况判断正确不低于 85%，其中不该出声却出声的不超过 10%；注入样例全部拦下。
- 每份报告记下服务、模型、提示词版本、策略、耗时与用量；用替身模型跑出的报告自动标注「仅流程」。

### 7.7 真人试用与前后测（E5）

- **可用性小样本**：5 到 8 位没有基础的用户，两个任务（一个动手做的、一个小工具），边做边说。看三件事：能不能看懂三条路线的差别并说出选择理由；
  回填后有没有改动再发；成果回来后知不知道做什么。
- **练习式前后测**：试用前后各做同一组练习——给三个模糊的想法，请用户写出自己会发给 AI 的那句话。按评分规则（目标是否清楚、要什么成果、怎么检查、条件是否交代）
  由裁判模型和人各评一次。前后分差就是「会不会自己搭脚手架」的变化。
- **策略对照**：不同的周用不同的策略（三条路线、只补一句、只改写一条、不开伴行），比较采用率、前后测增益和主观感受。
- 研究模式是单独的开关，有单独的知情同意，数据只在本机，导出由参与者自己操作。

## 9. 度量

全部在本机统计，只有数字。

**北极星**：用户发出去的那句话，是否越来越常是「原样可发」的——也就是脚手架在不在拆。指标：最近 20 份草稿中原样可发的比例，按周看趋势。

| 类别 | 指标 | 首轮假定目标 |
| --- | --- | --- |
| 来得及 | 来得及率 = 显示出来的次数 ÷（显示 + 迟到）；按档位分开看 | 不低于 60%；长期低于 50% 就要重新考虑出声的时机（见第 3 节 ⑬） |
| 有用 | 自动出现的气泡被采用的比例（按档位） | 带路不低于 35%；提点不低于 45% |
| 不打扰 | 被忽略的比例；自动降档后被改回的比例 | 改回不超过 20%（高了说明降得太急） |
| 快 | 从停顿到气泡第一行出现 | 提点 1.5 秒内；带路在流式下 2.5 秒内（均为中位数，取决于模型，待实测） |
| 稳 | 回填失败率；撤回率；出错率 | 在通过校准的版本上，回填失败低于 2% |
| 安全 | 误发送次数；认错聊天次数；写错输入框次数 | 恒为 0；出现即关闭对应能力 |
| 轻 | 伴行进程与 Codex 进程的 CPU | 见 A10 |
| 成长 | 原样可发比例的周变化；练习式前后测的分差 | 试用四周后比例上升；分差为正 |
| 主人翁 | 回填后改动过再发的比例（只记是否改动，不记内容）；提点档下自己补写而不点条目的比例 | 不设目标，只观察：改得多说明人在用自己的话 |

目标数字都是假定，第一次有真实数据后修订，并把修订理由写进台账。

## 11. 二代不做

- 不自动发送，不代替用户与 Codex 对话。
- 不截图、不看图识别屏幕。
- 不做账号、云同步、多人协作、教师端。
- 不做自己的模型服务；仍然由用户自带密钥，或接本机模型。
- 不自动更新程序本身（只提示有新版本）。
- 不为 Codex 以外的应用做专门的自动跟随适配。
- 不给多个 Codex 窗口各配一个桌宠；始终只跟前台那一个。
- 不在用户开口之前主动给模板或问题——人先行动这一条不破。
- 不做 Windows 以外的外壳（核心保持可移植，但不承诺）。
- 不让「同行」档自动回到更热闹的档位。

## 附录 D　规则的边界情形（写测试时逐条对照）

**三档与渐退（M2-03）**

- 档位变化（无论自动还是手动）都清空反馈窗口与可发窗口，并立即写入状态文件。
- 规则 A 在同行档不起作用；规则 B 在同行档不起作用。
- 规则 B 的询问被拒绝后记下时间，7 天内不再问；被接受等同手动降一档。
- 规则 A 自动降档后点「改回去」：回到原档位，窗口清空；之后重新累计，仍可能再次触发。
- 可发窗口只收自动分析、且被判为任务的草稿；用户主动要来的、非任务的都不进。
- 一条消息里先忽略后采用，只留采用；先采用后撤回，取消采用，若之前是忽略则恢复为忽略。

**补一句（M2-04）**

- 点补句时草稿已被用户改动：不写入，气泡收起，这一句可以复制。
- 写入失败：草稿不变，这一句可以复制；复制算采用。
- 正在写入时再点别的条目：忽略第二次点击。
- 连补两句：第二句接在「原话 + 第一句」后面；三重核对里的草稿是补过第一句之后的文本。
- 恢复原草稿：回到本条消息最初的原话；要求输入框里仍是伴行最后写入的那段文本。
- 没有写入能力：条目变为「点一下复制这一句」，标题相应改变。
- 提问式条目追加的是待填的开头；用户接着在后面打字属于正常编辑，气泡收起，但这段文本不再触发新的分析，直到有实质变化。

**路线与拼接（M2-02、M2-05）**

- 草稿末尾没有句末标点时补一个（中文句号或英文句点，按草稿的语言）；已有则不重复。
- `hold` 为真时原话放进引号，引号内不改动任何字符，包括原有的引号和换行。
- 三条里主线不是恰好一条、类型少于两种、任一后半段为空或过短：整个结果无效。
- 流式下点了后半段还没到的行：标记为等待；后半段到达时重新做三重核对，再写入；期间草稿变了就放弃并收起。

**迟到的备选（M2-13）**

- 只在输入框于同一聊天标识下由该草稿一步变空时保留；草稿是被改掉的、聊天是被切走的，都不保留。
- 保留十分钟；同一聊天里出现新的气泡时提前作废。
- 点开后选一条：按当前输入框的内容做核对（此时通常是空的）；不计入任何反馈。

**安全闸（M2-06）**

- 草稿或聊天片段里本来就有的地址，后半段里再出现不算外来。
- 只因为出现「删除」二字不算破坏性操作：要看是不是在要求 Codex 执行；「先列出将要删除的文件」这类带预览含义的写法放行。
- 丢弃一条后不足三条：整体无效，而不是显示两条。

**能力与校准（M1-01、M1-02）**

- 校准结果按「伴行版本 + Codex 版本」保存；任一变化都要求重新校准，未重新校准前按无能力处理。
- 校准中途取消：已完成的步骤不生效，保持原状态。
- 第五步写入测试结束后原稿没有复原：整个校准判为失败，写入能力关闭，并在结果页醒目提示。

## 三个问题

1. **致命：`Tcl_AsyncDelete: async handler deleted by the wrong thread`**
   （`test_shell.EntryPointTests.test_selftest_passes_its_required_checks_and_writes_a_report`）。
   自检的界面检查建了窗口又销毁，但对象之间互相引用，要等 Python 的循环垃圾回收才真正释放；
   下一项检查在另一个线程里加载 UI Automation，回收恰好在那个线程上发生，Tk 解释器被不是创建它的线程删除，Tcl 直接终止了进程。
   这不是测试的问题：打包后的 `--selftest` 走的是同一条路，正式运行退出时也可能遇到。
   修复在产品代码里：窗口由创建它的线程结束**并当场释放**（`PetApp.destroy`、`release_tk`），其他线程无权结束它；
   自检每一项结束后在本线程回收；另外查出模型配置窗口的变量监听会让整个解释器永远无法释放，已改为随窗口关闭而解除。
2. **`test_llm.LLMWireTests.test_unreachable_service_is_a_network_error` 失败。**
   这个用例用了 2 秒的超时，日志里它耗时约 2.7 秒。Windows 对本机已关闭端口的连接不会立刻拒绝，而是先重试约 2 秒，
   于是在得到「拒绝连接」之前先超时了。产品里的超时下限是 5 秒，不受影响；用例的超时已加长。
3. **`test_audit.FailClosedSecrets.test_a_working_dpapi_is_used_and_plain_values_are_not_accepted_on_windows` 失败。**
   用例里有一步假定「恢复原状 = 不是 Windows」，在真正的 Windows 上这一步用的是真的 DPAPI。是用例的错，已改。

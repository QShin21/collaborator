Windows 常规单测 406 项通过（7 项跳过），`tk,win32,uia` 必需自检通过。
单独的原生替身窗口 8 项中 7 项通过；粘贴用例仍报 `clipboard_busy`，草稿未贴入。
此次已能读取测试剪贴板的 Unicode 正文与 CF_LOCALE（格式 ID 为 `[13, 16, 1, 7]`，locale 句柄大小 4 字节）。

脱敏诊断显示：测试事前写入函数在剪贴板仍打开时取得序号 2，关闭并销毁短期 owner 窗口后读到序号 5；
粘贴尝试前为 5，失败后为 10，格式序列未变。这与 Windows 在关闭剪贴板时补充其他格式并推进序号相符，
但日志不能独立区分关闭动作和随后的 owner 销毁各自贡献了多少增量。
旧代码把写入时锁内序号当作关闭后的稳定序号；后续核对发现不一致，保守拒绝 Ctrl+V，恢复时也因序号不匹配
而不能安全覆盖当前内容。日志不包含剪贴板正文，因此不能仅凭 `clipboard_restored=False` 判定最终文本是什么；
此路径可能留下临时测试文本，不能把它当成功。

随后在本地实现临时剪贴板租约：一次性的随机私有标记和保持存活的 owner 窗口；关闭后重新加锁，
同时核对 owner、标记、正文、格式和 locale，才采纳新的稳定序号；贴入与恢复前再次核对并发变化。
不能用「关锁后裸取序号」冒认其他进程的新复制。此修复只有 E1，待下一次 Windows 活体重跑。

工作流整体显示 success，是因为替身测试步骤是 informational。真实 Codex 未运行；M0-03 仍未完成。

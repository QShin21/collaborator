# 证据台账

这份台账回答：**每一项现在有哪一级证据、依据是什么、还缺谁在什么环境下做什么。**
每次发布前更新。用语遵守方案 7.1：总是带等级；不单独写「已验证」「测试通过」「可用」；替身模型的结果只写「流程走通」。

## 1. 证据等级

| 等级 | 含义 | 说明得了 | 说明不了 |
| --- | --- | --- | --- |
| E0 | 只有设计或代码，没有运行过 | 意图 | 任何行为 |
| E1 | Linux 上的自动化测试：合成输入、模拟 Codex、替身模型、假服务端 | 我们自己的逻辑自洽 | Windows、Codex、真实模型的行为 |
| E2 | 真实 Windows（CI 机器或任意电脑），没有 Codex，对替身窗口 | 系统接口这一层能工作 | Codex 窗口的行为 |
| E3 | 真机：真实 Windows + 真实 Codex，人工操作，留有证据包 | 某个 Codex 版本上的实际行为 | 其他版本；路线质量 |
| E4 | 真实模型输出，经评测集或人工检查 | 路线质量（在该模型、该提示词版本下） | 用户是否受益 |
| E5 | 目标用户试用：前后测、访谈、记录 | 产品是否真的帮到人 | — |

## 5. 写在代码里的假设

全部集中在 `banxing/hosts/profile.py` 和 `banxing/context/`，可以单独调整；校准的作用就是逐条检验它们。

- Codex 桌面应用的进程名是 `codex.exe`；
- 输入框通过 UI Automation 暴露为可编辑元素，并能用 TextPattern 或 ValuePattern 读到未发送的文字；
- 在 Chromium 类编辑器里「全选 + 粘贴」会被编辑器正常接受；
- 微软拼音等输入法的候选窗口类名在默认列表里；
- 可执行文件的大小与修改时间足以区分 Codex 的版本（用作校准的有效范围）；
- App Server 的方法名、参数与返回字段如 `banxing/context/appserver.py` 文件头所述。

任何一条不成立，对应能力在校准里不会开启，伴行退到「粘贴草稿 + 复制」。

## 7. 自动化测试怎么跑

```
python -m unittest discover -s tests -v          # 全部；Windows 专用测试在其他系统上自动跳过
python run.py --selftest                         # 当前机器上的自检，--require tk,uia 可要求对应项必须通过
BANXING_PROVIDER=mock python run.py --eval       # 评测场景的结构检查；替身模型下只说明流程走通
```

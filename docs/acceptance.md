# 验收手册

给有真实数据、有 Windows、或有模型密钥的人照着做。**到写这份手册为止，下面没有任何一步被做过**——写的是要检查什么，不是已经观察到了什么。
做完按第 5 部分记一份记录，台账（[`verification.md`](verification.md)）里对应的行才能改等级。

规矩三条：

1. 如实记数。做了 20 次里有 1 次不对，就写 19/20，并写下那一次发生了什么。
2. 对话的文字不交给任何人。读错了只报**结构**（第几轮、哪种条目、数量）；报告文件里本来就只有轮次号和类型名。
3. 出现下面任何一种情况，立刻停下并在记录里标红：**账本或气泡引用了别的对话的内容；对话被发到了你没有在窗口里（或命令行上）同意过的地址；
   伴行往任何应用里写了东西。**

## 第 1 部分　读得对不对（不需要模型密钥，产出 E3）

```
python run.py --watch 导出.zip --list                      # 列出导出里的对话
set BANXING_PROVIDER=mock
python run.py --watch 路径 [--conversation ID]              # 读这一条；打印账本（离线替身的判断不作数）
```

| 编号 | 检查 | 做法 | 通过 |
| --- | --- | --- | --- |
| R1 | ChatGPT 导出 | 取 3 条自己的对话，各与网页上看到的当前分支对照 | 轮数一致 3；工具的运行与输出没有混进「主模型的话」3；附件、图片、别的分支在账本「读不到的部分」里有记 3 |
| R2 | 复制的聊天页面 | 在 3 个不同的网页聊天里全选、复制，用「从剪贴板读取」 | 轮数一致 3；用户的话和模型的话没有串 3 |
| R3 | Codex 会话 | 「旁听一条对话」→「Codex 最近的会话」，取 3 条 | 认得出是哪条 3；轮数一致 3；命令的输出读到了 3；最后一轮是否还在进行，与实际一致 3 |
| R4 | Claude Code 会话 | 取 3 个会话文件 | 轮数一致 3；工具结果记为「记录」而不是用户的话 3；子代理的内容没有混进来 3 |
| R5 | App Server | 装有 `codex` 命令时，R3 的列表来自 App Server | 与同一条对话的会话文件轮数一致；50 轮以上的对话读得全 |

## 第 2 部分　在 Windows 上（需要模型密钥或离线替身，产出 E2/E3）

| 编号 | 检查 | 做法 | 通过 |
| --- | --- | --- | --- |
| U1 | 启动与自检 | `Banxing.exe --selftest --require tk,win32` | 退出码 0 |
| U2 | 不抢焦点 | 在聊天窗口里打字时让气泡出现（可用离线替身和文字稿）；点气泡上四个按钮后直接继续打字，各 5 次 | 字都进了聊天窗口 20；光标没有离开 20 |
| U3 | 复制追问 | 点「复制这句追问」后在聊天里粘贴，10 次 | 粘贴出来的与气泡里的一字不差 10；伴行没有自己往聊天里写任何东西 10 |
| U4 | 文件更新 | 旁听一个 Codex 或 Claude Code 会话，正常工作 20 轮 | 每轮结束后账本的「已读到第 N 轮」跟上 20；记下从一轮结束到审查开始、到气泡出现各用了多久 |
| U5 | 发出下一条 | 气泡还在时发出下一条消息，10 次 | 旧气泡收起 10 |
| U6 | 换分支 | 改写一条早先的消息，5 次 | 伴行停下并要求确认 5；确认之前「使用范围」里的请求次数不变 5 |
| U7 | 同意 | 旁听中把接口地址换成另一个（设置或环境变量） | 不再有任何请求；账本要求重新同意 |
| U8 | 保存 | 勾选「加密保存这本账」，退出再打开 | 账本还在；`vault\watch.bin` 用记事本打开看不到任何对话文字；「结束旁听」后该文件消失 |
| U9 | 使用范围 | 对照模型服务商后台的请求记录 | 账本上的请求次数与后台一致（含回头查和独立一读的那几次） |
| U10 | 托盘与多显示器 | 隐藏到托盘再找回；把图标拖到另一块屏幕 | 找得回；气泡出现在图标旁、不出屏幕 |

## 第 3 部分　判断好不好（需要模型密钥，产出 E4）

```
python run.py --replay --agree https://实际地址 --report replay.json            # 11 段带标注的合成对话
python run.py --watch 路径 --conversation ID --stepwise --agree https://实际地址 --report steps.json   # 自己的一条真实对话
```

- `replay.json`：时机（在窗口内提出几次、富余几轮、错过几次）、准头（类型、引文是否指到了该指的地方）、误打扰（该安静时出声、过早、
  回应之后又弹）、主动性（回头查了几次、搜了几次、做了几次独立一读、花了多少请求）、一次性对照。
  **特别看对照**：同一个模型在关键轮次只读一次，如果做得一样好，逐轮旁听就没有带来东西。
- 真实对话：逐轮回放后由**对话的主人**逐条判断，只记数——
  - 出声的每一处：是不是真的问题；引的原文是不是真能支持它；那句追问发给主模型，对方答不答得上来；来不来得及。
  - 没出声的地方：有没有哪一轮本该提醒（事后你自己知道这段对话在哪里走偏了）。
  - 合理的深挖、你有意的转向、措辞谨慎的结论——这些时候出声了几次。
- 换一个旁听模型（最好与对话里的主模型不是同一家）再做一遍，记下差别。

## 第 4 部分　有没有用（试用，产出 E5）

这个应用要回答的是：**一段长对话走偏的时候，用户是不是更早知道了。** 试用时记：

- `python run.py --summary`：出声几次；带回去问几次；「有意如此」几次；「不成立」几次（`wrong_rate`）；后来被记录解决几次。
  「不成立」长期高于三成，说明它在添乱。
- 每周挑一段已经结束的长对话，自己回头看：真正走偏的那个点，伴行当时说了没有；说了的话，早了几轮。
- 复制出去的追问，主模型的回答有几次改变了后面的方向。

## 第 5 部分　交回什么

一份记录，文件名 `docs/evidence/EV-年份-序号.md`：日期、执行人、机器与系统版本、伴行版本、旁听用的服务与模型、提示词版本、
做了哪几项、逐项的数字、没做的项。`replay.json` / `steps.json` 可以附上（里面没有对话文字）；账本的截图含有对话内容，自己留着。

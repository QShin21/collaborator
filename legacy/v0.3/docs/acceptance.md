# 真机验收手册

给有 **Windows 10/11 + 已登录的 Codex 桌面应用** 的人照着做。做完得到的是 E3 证据（见 [`verification.md`](verification.md)）。
到写这份手册为止，**还没有人做过其中任何一步**——下面写的是要检查什么，不是已经观察到了什么。

规矩只有三条：

1. 如实记数。做了 30 次里有 1 次不对，就写 29/30，并写下那一次发生了什么。
2. 不留存任何草稿或聊天文字。验收用自己随手编的句子；记录里只写数量和是否。
3. 出现下面任何一种情况，立刻停止并在记录里标红，对应能力在该版本直接关闭：
   **发送了用户没有发送的东西；写进了错误的输入框；引用了错误聊天的内容。**

## 准备

- 从 Releases 下载 zip 解压，或从源码 `pip install -r requirements-windows.txt` 后 `python run.py`。
- 记下：Windows 版本、缩放比例、显示器数量、输入法、Codex 版本、伴行版本（菜单「关于」）。
- 模型：有密钥就在「模型配置」里配置；没有密钥时第 1 部分照样能做，第 2 部分只能做 A1、A3 的读稿与输入法部分。
  用离线替身模型做出来的任何结果只能写「流程走通」。

## 第 1 部分　校准（约 3 分钟）

右键伴行 → 「校准（开启自动跟随）」。向导一步一步提示；每一步的判断都用固定的测试短语，不保存你写的字。

| 步骤 | 你做什么 | 向导检查什么 | 没通过意味着 |
| --- | --- | --- | --- |
| C1 认窗口 | 点一下 Codex 窗口 | 前台进程是不是 Codex | 进程名不同：把证据包发给开发者 |
| C2 读稿 | 在输入框里输入屏幕上给出的短语 | 读到的是否与短语一致；同时记下输入框的特征 | 没有「读」的能力：只能粘贴草稿 |
| C3 空输入框 | 清空输入框 | 读到的是否为空（否则记为占位文字） | 占位文字会被当成草稿 |
| C4 输入法 | 用输入法打一句中文，选词时停两秒 | 只记录出现了哪些信号，不判对错 | — |
| C5 回填 | 等待 | 写入一个标记再去掉，原稿是否复原 | 没有「写」的能力：点路线变为复制 |
| C6 焦点 | 点一下测试气泡，然后直接打一个字 | 那个字有没有进输入框 | 浮窗会抢焦点：结果页有醒目提示 |
| C7 聊天 | 切到另一个聊天再切回来 | 聊天标识是否变化并回到原值 | 不能区分聊天：不参考聊天内容 |
| C8 会话数据 | 等待 | 能否读到这个聊天的历史（只看结构和数量） | 只依据草稿 |
| C9 性能 | 等待 | 读一次窗口要多久 | 读取太慢：结果页有提示 |

结束后：

1. 把结果页抄进记录（每步 ✓ / ✗ / –，开启了哪些能力）。
2. 右键伴行 → 「导出证据包」，先在窗口里通读一遍（应当**没有任何你写过的字**；有的话这本身就是一个必须报告的问题），再保存。
3. 关掉伴行再打开，确认不需要重新校准；如果 Codex 自动更新了版本，确认伴行要求重新校准。

## 第 2 部分　计数验收

在通过校准的机器上做。数字是首轮假定的门槛，第一次实测后按实际情况修订并写进台账。

| 编号 | 检查 | 做法 | 通过 |
| --- | --- | --- | --- |
| A1 | 读稿准确 | 20 段不同的草稿：多行、中英混排、带符号；每段用「粘贴草稿」窗口之外的办法比对——看气泡预览里「你的原话」一段 | 20 次都与所见一致 |
| A2 | 停顿触发 | 20 次写完停手 | 20 次都在 1 到 2 秒内进入「正在想」 |
| A3 | 输入法 | 用拼音打 30 句，每句选词时故意停两秒 | 选词期间触发分析 0 次 |
| A4 | 回填 | 30 次选一条路线 | 内容一致 30；未被发送 30；光标在输入框 30；剪贴板复原 30 |
| A5 | 不抢焦点 | 点气泡或伴行后直接打字，30 次 | 字进入 Codex 30 |
| A6 | 聊天切换 | 两个聊天来回切 20 次，各有草稿 | 旧气泡每次都收起；迟到结果显示在错误聊天里 0 次 |
| A8 | 补一句 | 提点档下 20 次补句，其中 5 次连补两句 | 草稿 = 原话 + 所补句子，逐字一致 20；恢复原草稿成功 5 |
| A9 | 安全 | 在 Codex 设置页的输入框、登录框里打字并停顿 | 触发分析 0 次 |
| A10 | 性能 | 开着伴行正常使用 30 分钟 | 伴行进程 CPU 空闲时低于 1%、打字时低于 3%；Codex 进程 CPU 与不开伴行时相比差不超过 2 个百分点 |
| A11 | 稳定 | 连续运行 8 小时 | 无崩溃；内存增长不超过 30 MB |

A7（认聊天的绑定）和 A12（成果到达）对应的功能本版没有实现，不做。

另外请留意并记下（不计数，但要写）：

- 多显示器、高缩放比例下伴行和气泡的位置；两个 Codex 窗口并排时跟随哪一个。
- Codex 正在生成回答时写下一条草稿，气泡是否正常。
- 涉及删除、提权的路线是否先展开预览而不是直接填入。
- 草稿发出后才回来的路线：是否只出一句提示；点伴行能否看到；十分钟后是否消失。
- 连着关掉四次气泡后是否降一档并能一键改回。

## 第 3 部分　路线质量（需要模型密钥，产出 E4）

```
python run.py --demo "（自己编一句想做的事）" --agree https://实际的接口地址
python run.py --eval --report eval.json
```

报告里有服务、模型、提示词版本和每个场景的结构检查结果。把 `eval.json` 和一句结论记进 `docs/evidence/`。
结构检查只说明格式与规则；路线好不好还需要人看——抽十个场景，逐条判断：三条是否真的不同、第一份成果能不能检查、草稿里的条件有没有丢。
裁判模型打分和盲评导出本版没有实现。

## 第 4 部分　交回什么

按 [`evidence/TEMPLATE.md`](evidence/TEMPLATE.md) 写一份记录，文件名 `EV-年份-序号.md`，连同证据包 zip 的文件名一起交给协调方。
协调方把记录放进 `docs/evidence/`，在台账对应的行里改等级并加链接；证据包里的 `structure.json` 交给实现者做成回放测试。

旧代码只有这一种失败描述；日志**没有**记录 `SendInput` 是否注入了快捷键、文本框里最后是什么、剪贴板是否恢复，
因此不能把失败归因于某一个具体的 Windows 调用，也不能拿这个结果证明草稿或剪贴板安全。
该步骤在工作流中标为 `continue-on-error`，所以工作流显示成功，**不代表**粘贴回填通过。

修复中的代码将快捷键合成一个批次，检查注入结果，并区分「未注入」与「未送达」；部分注入时只补发仍按下的键的抬键事件。
只借用能以 Unicode 文字复原的剪贴板，按变更序号恢复，避免覆盖用户在此期间的新复制；
更换失败时在同一把锁下回滚原文字，连回滚也失败则明确报错而不注入键；
失败路径不再盲目二次写入用户可能已改过的草稿。替身用例也会在失败时报告草稿、剪贴板是否仍与预期相符。
这些是本地 E1 回归，**尚未在 Windows 上重跑**。如果新运行仍然报告未送达，必须在可交互的 Windows 桌面上验证
`SendInput`；不能把 ValuePattern 通过当作粘贴通过，更不能在真实 Codex 上预设它能工作。
锁内检查无法消除最后一次检查到 Codex 实际处理粘贴之间的系统级焦点/剪贴板竞态；
恢复 Unicode 正文也不等于保留所有剪贴板元数据。这些剩余风险需要真机验收，不能声称绝对安全。
